# 沙盒输入/输出挂载设计（/input 只读 · /output 自动回收）

> 状态：**设计稿（待拍板）** —— 2026-10-29。
> 目标读者：平台与 pi-web 维护者。
> 一句话：把"用户工作区"与"容器文件系统"的关系从**单向复制种子**升级为
> **选择性只读输入挂载（/input）+ 定向输出挂载（/output）自动回收**，
> 并顺带修复 restart 丢 bind 的既有缺口。

## 一、现状与问题（代码事实）

| 链路 | 现状 | 来源 |
|---|---|---|
| 工作区种子 | 创建容器可带 `workspaceId` → `seedFromPath` → 三种执行器三种语义：SSH=**bind RW**、CLI/Mock=**复制** | `container.service.ts:218`、`ssh-executor.ts:107`、`apptainer-cli-executor.ts:130` |
| 容器重启 | `start()` 重建实例**不重放 seed/bind**——SSH 形态下 stop→start 后 /workspace 变空（reaper 自动停启同样触发） | `container.service.ts:288`（create 调用无 seedFromPath） |
| 输入 | 容器内 /workspace 既是输入载体又是草稿区，**RW 无隔离**——Agent 可改写/删除用户输入 | 上述 bind 无 `:ro` |
| 输出 | 无产物通道：容器内写的一切留在 overlay，**容器销毁即丢**；pi-web 侧靠工具中转手抄 | — |
| 平台工作区 | 已有完整用户工作区（上传/下载/树/分块上传/配额），`storage.workspaceDir(userId, wsId)` 落在平台宿主机 | `workspaces.routes.ts`、`workspace.service.ts` |

## 二、目标语义（对用户的承诺；2026-10-29 拍板后修订）

1. **/input**：**不做整工作区挂载**——`/input` 是一个每容器独立的**输入暂存目录**的
   只读 bind（`:ro`，内核强制）。"挂载"= 用户从"我的工作区"挑选**文件或子目录**，
   平台将其物化（复制）进暂存目录，容器内以 `/input/<名称>` 即刻可见；
   **运行中可继续追加/移除挂载项（无需重启容器）**。内容以添加时点为准
   （工作区后续修改不自动同步；需要更新就删掉重加）。
2. **/output**：容器内定向输出目录，live bind 到工作区 `outputs/<容器名>/`
   （**写入即出现在"我的工作区"**，仅允许此前缀）。模型自行决定什么进 /output
   （最终交付物）、什么留在 /workspace（不想持久化的中间结果）。
   容器销毁/重建/快照回滚都不影响已回收产物。
3. **/workspace**：保留为**草稿区**（overlay 支撑、不 bind），Agent 干活的地方，
   兼容现有工作流与 pi-web 的 sync。

### 拍板记录（2026-10-29）

- 输入运行中可追加：**允许**（暂存目录方案天然支持）。
- /workspace：**保留**（Agent 干活草稿区）。
- 输出约束：**仅 `outputs/<容器名>/` 前缀**（live bind 到宿主指定目录）。
- 单容器输入规模上限：**1GB/32 项**。
- SSH 远端形态（平台经 SSH 连到跑 apptainer 的远端节点）：暂按"远端暂存 +
   回收"设计延后（P2）；**回收通道不用 rsync**（内网 Rocky8/CentOS7 不保证
   存在）——改用 `tar 流 over SSH exec`（仅依赖 tar+coreutils）。

## 三、数据模型与 API

### 3.1 挂载持久化（同时修复 restart 缺口）

```
container_mounts(
  id INTEGER PK,
  container_id INTEGER NOT NULL,      -- FK containers
  kind TEXT NOT NULL,                 -- 'input' | 'output'
  workspace_id INTEGER NOT NULL,      -- FK workspaces（归属校验 requireOwned）
  rel_path TEXT NOT NULL,             -- 工作区内相对路径（输入项或输出子目录）
  mount_path TEXT NOT NULL,           -- 容器内路径：/input/<name> 或 /output
  created_at ...
)
-- containers 表另存 output_workspace_id 可空（输出宿主工作区）
```

`start()` 重建实例时按表重放全部 binds；`seedFromPath` 机制并入 mounts
（兼容期：`workspaceId` 种子等价注册为 `input(rel_path="/", mount=/seed,
快照语义)`，见 §四拓扑分层）。

### 3.2 路由（containers.routes.ts 扩展）

```
POST   /api/v1/containers            body 增：mounts: { inputs: [{workspaceId, path}],
                                                output?: {workspaceId, subdir?} | true }
GET    /api/v1/containers/:id        返回解析后的 mounts（含容器内路径）
PATCH  /api/v1/containers/:id/mounts 仅 stopped 状态可改（422 否则）
GET    /api/v1/containers/:id/outputs?path=   产物浏览（透传工作区文件 API，
                                               便于前端一个入口）
```

校验：`workspaceId` 归属当前用户；`path` 规范化后必须落在 `workspaceDir` 内
（禁 `..`/绝对路径/符号链接——输入项 `lstat` 拒绝 symlink）；单个容器输入
项 ≤ 32 个、路径深度 ≤ 16（防 bind 参数爆炸）。

## 四、执行器拓扑与语义分层（关键设计）

三种执行器/两种拓扑决定"live 还是快照"，**契约对用户统一表述**：
输入"只读、以启动时点为准（同机为 live）"；输出"最终必然回到工作区"。

| 执行器（拓扑） | /input 实现 | /output 实现 |
|---|---|---|
| **apptainer-cli**（平台与容器同机，start-all 默认部署） | `--bind <workspaceDir>/<rel>:/input/<name>:ro` **live**：工作区上传/替换即时可见 | `--bind <workspaceDir>/outputs/<容器名>:/output` **live RW 零拷贝**：写入即出现在"我的工作区" |
| **ssh**（容器在远端节点） | create/start 时 `putDirectory` 到远端 staging → `--bind :/input/<n>:ro`（**快照**；重启即刷新） | 远端 staging `--bind :/output` RW + **回收**：stop/snapshot 前、以及可配置轮询 `rsync --delete` 拉回工作区子目录 |
| **mock**（win32 开发） | 直接使用真实路径（命令本就跑在宿主），ro 尽力（文档标注开发近似） | 同左，输出直接写工作区子目录 |

SSH 回收时点默认：**stop 与 destroy 前强制回收 + 5 分钟轮询兜底**；
回收失败阻塞 destroy（提示先手动取回）。

## 五、安全清单（本设计的硬前置）

1. **只读强制**：`:ro` 由内核执行；工具中转（fs.write）对 /input 报错属预期。
2. **宿主路径封闭**：mounts 只能由 (workspaceId, relPath) 推导，服务端 resolve
   并二次校验落在 `storage.workspaceDir` 内；API 永不接受裸宿主路径。
3. **符号链接逃逸（现状缺口，需一并加固）**：SSH 形态今天的 RW bind 已允许容器
   在工作区创建符号链接，而 `workspace.service` 的读/列/删**未见 realpath 防护**——
   容器可造 `outputs/x -> /etc/passwd` 再经工作区 API 读出。本设计落地时必须：
   workspace 文件服务全部 `realpath` 校验不逃出根；outputs 目录内 symlink
   一律跳过/拒绝并可管理端告警。
4. **配额**：/output 计入工作区配额（复用 quota.service；回收同步前先查剩余
   配额，超限转为告警+部分回收）。
5. **多租户隔离**：bind 目标唯一化为 `<workspaceDir>/outputs/<容器实例名>`，
   不同容器/用户天然不交叉；destroy 只清 overlay，不动工作区产物。

## 六、pi-web / WebUI 集成

1. **创建与设置**：沙盒容器创建页 + 项目沙盒设置增加"输入挂载"选择器
   （我的工作区树、多选文件/目录）与"输出回收"开关（默认开，目标
   `outputs/<容器名>/`）；只读徽标提示。
2. **会话提示**：sandbox 会话的 environment-info 增加：
   `/input=用户输入(只读)、/workspace=草稿区、/output=交付物写入处(自动回收)`，
   引导模型把最终产物写 /output。
3. **产物呈现**：零新增——产物即时出现在"我的工作区" outputs/ 下；会话文件
   面板把 /input、/output 映射为两个虚拟根（经现有 tools 中转浏览）。
4. **兼容**：pi-web 侧 `syncWorkspaceToContainer`（写 /workspace）保留为
   草稿区初始化；后续可按项目开关关掉。
